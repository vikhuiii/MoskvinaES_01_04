Кредитный калькулятор (Bank)

Техническая презентация · Android · Kotlin · вариант 4

Учебный проект: мобильное приложение для расчёта ежемесячного платежа по кредиту со снижающейся процентной ставкой. Цель слайдов — показать реализацию, а не продать продукт.

Android Kotlin Android Studio Офлайн release-APK 1.0 ≈ 2 МБ

1. Задача и контекст

Что должно делать приложение
  • Авторизация (логин/пароль) на экране Bank.
  • Выбор суммы кредита слайдером (30 000 – 100 000 ₽).
  • Ввод срока в месяцах и мгновенный расчёт платежа.
  • Расчёт по периодам при сроке > 12 мес. со снижающейся ставкой: 5,9% → 5,1% → 4,2%.
  • Отдельный экран результата; возврат в главное меню.
  • Работа без интернета — все вычисления на устройстве.

Слои

  • UI — Activity + XML-разметки, обработка ввода, валидация.
  • ViewModel — хранение состояния экрана, вызов логики расчёта.

  • Data — in-memory сессия (без БД и сети).

Такой выбор обоснован учебным характером проекта: минимум зависимостей, максимум прозрачности кода.

5. Реализация расчёта

Формулы варианта 4 (аннуитет с дифференцированной ставкой по периодам)
ПериодСтавкаФормула
1–12 мес.5,9%s₁ = S/n + S·0,059
13–24 мес.5,1%s₂ = S/n + (S−P₁₂)·0,051
с 25-го мес.4,2%s₃ = S/n + (S−P₂₄)·0,042

S — сумма кредита, n — срок в месяцах, P₁₂ / P₂₄ — выплаченная сумма за 12 / 24 месяца. Результат выводится в тыс. рублей.

// Kotlin (упрощённо)
fun compute(S: Int, n: Int): PaymentPlan {
    val periods = mutableListOf<Period>()
    var paid = 0.0
    for (m in 1..n) {
        val rate = when {
            m <= 12 -> 0.059
            m <= 24 -> 0.051
            else    -> 0.042
        }
        val payment = S.toDouble() / n + (S - paid) * rate
        paid += S.toDouble() / n
        periods += Period(m, m, rate, payment / 1000) // в тыс. ₽
    }
    return PaymentPlan(periods)
}

Почему быстро

  • Нет сетевых вызовов и сериализации.
  • Расчёт — O(n) по числу месяцев, без аллокаций в цикле кроме списка периодов.
  • ViewBinding устраняет findViewById и ускоряет биндинг.
  • Слайдер обновляет UI через setOnChangeListener без перерисовки тяжёлых компонентов.
